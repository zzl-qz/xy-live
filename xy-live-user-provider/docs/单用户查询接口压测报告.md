# 单用户查询接口性能压测报告
## 一、测试背景
本次测试针对单用户查询接口，旨在验证当Dubbo最大连接数设置为1000时，接口在不同线程数（100、500、1000、1300、1500、2000）压力下的性能表现，为系统的性能优化和容量规划提供依据。

## 二、测试环境
- **Dubbo配置**：最大连接数设为1000。
- **压测工具**：[JMeter]。
- **服务器配置**：[]。

## 三、测试指标及说明
- **样本数**：压测过程中发送的请求总数。
- **平均值**：请求响应时间的平均值，反映整体响应速度水平。
- **最小值**：请求响应时间的最小值，体现最快响应情况。
- **最大值**：请求响应时间的最大值，体现最慢响应情况。
- **标准偏差**：反映响应时间的离散程度，值越小说明响应时间越稳定。
- **异常率**：异常请求数占总请求数的比例，体现接口的稳定性。
- **吞吐量**：单位时间内处理的请求数，反映接口的处理能力。
- **接收/发送KB/sec**：单位时间内接收/发送的数据量，体现数据传输效率。
- **平均字节数**：每个请求的平均数据字节数。

## 四、测试结果分析
### （一）线程数为100时
- **样本数**：3518679，请求量较大。
- **响应时间**：平均值为7，最小值0，最大值216，标准偏差1.96，响应时间整体较优且稳定。
- **异常率**：0.00%，接口稳定性极佳。
- **吞吐量**：11730.5/sec，处理能力较强。
- **数据传输**：接收985.17KB/sec，发送2709.67KB/sec，平均字节数86.0，数据传输效率良好。

### （二）线程数为500时
- **样本数**：3397806，请求量有所变化。
- **响应时间**：平均值41，相比线程数100时上升，最小值0，最大值185，标准偏差8.58，响应时间稳定性有所下降。
- **异常率**：0.00%，接口仍稳定。
- **吞吐量**：11323.4/sec，较线程数100时略有下降。
- **数据传输**：接收950.99KB/sec，发送2615.64KB/sec，平均字节数86.0，数据传输效率有一定降低。

### （三）线程数为1000时
- **样本数**：3485242。
- **响应时间**：平均值82，进一步上升，最小值0，最大值1642，标准偏差28.67，响应时间波动增大，稳定性明显下降。
- **异常率**：0.00%，接口未出现异常请求。
- **吞吐量**：11611.1/sec，处理能力有波动。
- **数据传输**：接收975.26KB/sec，发送2682.09KB/sec，平均字节数86.0，数据传输效率继续变化。

### （四）线程数为1300时
- **样本数**：3775948。
- **响应时间**：平均值98，持续上升，最小值0，最大值663，标准偏差46.91，响应时间离散程度加大。
- **异常率**：49.98%，接口开始出现大量异常，稳定性急剧恶化。
- **吞吐量**：12578.9/sec，处理能力虽有数值提升，但异常率高，实际有效处理能力大减。
- **数据传输**：接收13437.77KB/sec，发送1453.49KB/sec，平均字节数1093.9，数据传输相关指标变化显著，与异常情况相关。

### （五）线程数为1500时
- **样本数**：3566091。
- **响应时间**：平均值117，继续上升，最小值0，最大值22996，标准偏差422.66，响应时间极不稳定。
- **异常率**：55.80%，异常率进一步升高，接口稳定性极差。
- **吞吐量**：11878.7/sec，处理能力受异常影响，有效性能大降。
- **数据传输**：接收14611.45KB/sec，发送1212.72KB/sec，平均字节数1259.6，数据传输情况复杂。

### （六）线程数为2000时
- **样本数**：3554641。
- **响应时间**：平均值157，达到较高水平，最小值0，最大值1037，标准偏差85.99，响应时间波动大。
- **异常率**：57.01%，异常率仍处于高位，接口稳定性难以保障。
- **吞吐量**：11835.6/sec，处理能力受异常拖累，实际效果差。
- **数据传输**：接收14418.44KB/sec，发送1175.35KB/sec，平均字节数1247.5，数据传输相关指标表现不佳。

## 五、结论与建议
### （一）结论
当线程数在100 - 1000范围内时，接口整体表现较好，异常率为0，响应时间虽随线程数增加有上升，但在可接受范围内，吞吐量等指标也能维持较好水平；当线程数超过1000（如1300、1500、2000）时，异常率急剧上升，响应时间稳定性大幅下降，接口性能严重恶化，虽Dubbo最大连接数设为1000，但线程数过大时，仍无法支撑，导致大量请求异常。

### （二）建议
1. 单用户查询接口的最优线程数建议控制在1000以内，以保证接口的稳定性和性能。
2. 针对线程数超过1000时出现的异常情况，需进一步排查Dubbo连接管理、服务端处理能力等方面的问题，优化系统架构，提升接口在高并发场景下的性能。
3. 可考虑对接口进行分层优化，或增加服务端资源，以应对更高的并发需求。
