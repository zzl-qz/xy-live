# 用户服务模块（xy-live-user-provider）设计亮点文档

> **所属模块**：`xy-live-user-provider` ｜ **上级索引**：[文档索引](../../docs/README.md) ｜ [项目 README](../../README.md)

## 一、高并发性能优化设计

1. **多层次缓存策略**
    - 实现"布隆过滤器+Redis+数据库"三级缓存架构，有效防止缓存穿透和雪崩
    - 缓存过期时间添加随机抖动（`ThreadLocalRandom.nextLong(1000)`秒），降低缓存雪崩风险

2. **读写分离与分表设计**
    - 基于ShardingSphere实现MySQL读写分离，主库写入、从库读取
    - 核心表（t_user、t_user_tag、t_user_phone）按user_id取模分100表，降低单表压力
    - 分表算法采用INLINE策略，表达式为`user_id % 100`，实现简单高效的水平分片

3. **高并发登录优化**
    - 登录接口支持注册登录一体化，减少用户操作链路
    - 压测结果导向的优化策略：500线程下通过调整数据库连接池、优化Redis缓存命中率提升稳定性
    - 非核心逻辑（如登录日志）支持异步处理，减少同步请求耗时

## 二、并发安全设计

1. **分布式锁机制**
    - 基于Redisson实现分布式锁，控制并发场景下的数据一致性
    - 锁超时策略：尝试获取锁等待5秒，自动释放时间30秒，平衡性能与安全性
    - 锁键命名规范：`lock:user:phone:{phone}`、`lock:user:info:{userId}`等，粒度精细

2. **标签操作并发控制**
    - 标签设置采用"更新→删除缓存→延迟消息二次删除"机制，解决并发读写不一致
    - 首次设置标签时通过分布式锁防止并发插入重复数据
    - 延迟双删策略：同步删除缓存后，发送1秒延迟消息再次删除，确保缓存一致性

## 三、代码架构亮点

1. **领域边界清晰**
    - 核心领域划分：用户账号、手机号、标签三大模块，职责单一
    - 服务接口设计：IUserService（用户信息）、IUserPhoneService（手机号登录）、IUserTagService（标签管理），边界明确

2. **缓存键规范管理**
    - 统一的缓存键生成策略，如`user:info:{userId}`、`user:tag:{userId}`
    - 缓存TTL统一设置（30分钟），结合随机抖动，兼顾性能与一致性

3. **高效批量处理**
    - 批量查询用户信息采用"布隆过滤→Redis批量获取→数据库并行查询→缓存回填"流程
    - 分表查询时使用并行处理，最多100线程（对应100张分表），1k用户批量查询响应时间约40ms

## 四、可靠性设计

1. **缓存异常防护**
    - 布隆过滤器防止缓存穿透：查询前先判断元素是否存在，不存在直接返回
    - 缓存雪崩防护：过期时间随机化+Redisson的`trySetMulti`原子写操作
    - 延迟双删机制：通过RocketMQ延迟消息实现缓存二次删除，解决更新后缓存不一致问题

2. **数据库操作安全**
    - 标签更新采用行级锁，通过`update ... set tag_bit=tag|4`实现原子操作
    - 事务控制：用户注册时同时插入t_user、t_user_phone、t_user_phone_index，保证数据一致性

## 六、性能测试与优化闭环

1. **完善的压测体系**
    - 针对登录接口进行多线程（100/500线程）压测，核心指标包括响应时间、异常率、吞吐量
    - 压测结果分析：100线程下平均响应241ms，500线程下针对性优化数据库连接池和缓存策略

2. **数据驱动的优化建议**
    - 基于压测结果提出具体优化方向：调整数据库连接池、SQL优化、异步处理非核心逻辑
    - 环境优化建议：采用分布式压测或测试环境服务器，避免本地资源成为瓶颈
