# XY LIVE 前端

> **所属目录**：`front/` ｜ **上级索引**：[文档索引](../docs/README.md) ｜ [项目 README](../README.md)

独立的 React + TypeScript + Vite 前端，放在仓库的 `front/`，不加入 Maven 构建，也不修改后端。

## 启动

```bash
cd front
npm install
cp .env.example .env
npm run dev
```

打开 `http://localhost:5173`。Windows PowerShell 可用 `Copy-Item .env.example .env`。生产构建运行 `npm run build`。

Vite 将 `/api` 代理到 `VITE_BACKEND_ORIGIN`，默认是 `http://localhost:9191` 网关。网关路由由 Nacos 配置，仓库里没有实际路由前缀；若网关使用 `/live/api`，请在 `.env` 里设置 `VITE_BACKEND_PREFIX=/live/api`。部署静态文件时，需要在 Web 服务器把 `/api` 反向代理到同一路由，或者通过 `VITE_API_ORIGIN` 指定完整的 API 前缀后重新构建。

## 已接入的能力

- 直播间列表：普通直播和 PK 列表、分页、搜索与进入房间。
- 手机验证码登录：保存登录响应的 token，并在 API 请求中发送 `Xytk` 头。
- 直播间：开播、关播、房间信息、WebSocket 实时聊天、心跳与消息 ACK。
- 互动：礼物列表与送礼、主播红包雨和观众抢红包、账户余额。
- 商城：商品列表、购物车 v2 与预下单。价格按后端扣款逻辑显示为星币。

PK 房间可在发现页筛选和进入，但当前礼物按普通礼物赠予主播，暂不计入 PK 进度。后端没有查询当前挑战者的接口，挑战者下线也没有通知；直接使用 PK 送礼类型可能先扣星币却没有礼物反馈。完整 PK 计分需后端提供可验证的实时连线状态。

后端未提供推流服务、视频播放地址或聊天历史接口。播放器支持 HLS (`.m3u8`) 以及浏览器原生可播放的视频地址；可设置 `VITE_STREAM_URL_TEMPLATE`（用 `{roomId}` 代入房间号），也可在直播间为每个房间输入播放地址。主播摄像头按钮只在本机预览，不会把画面推给观众。真实直播需要另行部署媒体服务，并保证播放地址的跨域配置允许浏览器访问。HTTPS 页面需要可访问的 WSS 地址；后端 `/im/getImConfig` 返回的地址必须能从观众浏览器访问。

预下单接口只返回布尔值，没有应付金额或订单号，且支付接口会结算该用户在当前房间的所有待支付订单。前端因此不会直接发起扣款；要完成安全的支付体验，需要后端返回可核对的订单明细与金额。红包配置也需要先在后端准备；当前 HTTP API 没有创建红包配置的入口。

后端不可访问时，发现页明确标注并显示界面预览内容；该内容不代表真实直播，登录、礼物和购物不会在预览房间发请求。后端返回空列表时显示空态，不会补入示例房间。
