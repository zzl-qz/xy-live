Features

一套完整的直播业务闭环

从开播、互动到付费结算的完整链路。每个业务域独立成服务，服务之间通过 Dubbo 同步调用、通过 RocketMQ 异步解耦。

直播房间

开播与关播、房间分页与搜索、房间信息查询，支持普通直播与 PK 连麦两种房间形态。

即时通讯

基于 Netty 的长连接服务器，WebSocket 与 TCP 双协议，含握手鉴权、心跳保活与在线消息路由。

礼物打赏

礼物配置、送礼记录与 PK 场景计分，送礼结果通过 RocketMQ 驱动下游账户扣款，保证最终一致。

红包雨

主播发起红包、观众抢红包并完成结算。抢红包结果异步入队处理，削峰填谷保障互动体验。

直播间商城

商品与 SKU、购物车、预下单、支付回调，配合库存扣减、超时回滚与订单状态订正任务。

虚拟账户

星币账户余额与交易流水，统一的支付网关衔接订单结算、余额扣减与异步支付回调。

Architecture

清晰的分层与依赖方向

接入层负责协议适配与参数编排，业务服务之间按 Dubbo 同步调用、按 RocketMQ 异步解耦， 所有服务统一注册到 Nacos。

客户端 网关与长连接 业务微服务 基础设施

分层约定

每个业务域拆成 -interface 与 -provider。前者只放 Dubbo 接口、DTO 与枚举， 不依赖 Spring；后者放实现、DAO 与 Spring 配置。

接入层不碰数据库

xy-live-api 只做参数校验、上下文透传与 RPC 编排， 所有持久化逻辑下沉到 provider，保证边界清晰。

异步优先

送礼、支付、库存回滚等跨域写操作统一走 RocketMQ 事件， 主链路只做必要的强一致校验。

Quick Start

四步跑起整套服务

需要自备 Nacos、MySQL、Redis 与 RocketMQ。服务配置由 Nacos 下发， 仓库内只保留引导配置，因此第三步不能跳过。

依赖组件与默认端口
# 必备
JDK        17+
Maven      3.8+
Nacos      2.x     :8848
MySQL      8.0     :3306
Redis      6+      :6379
RocketMQ   4.9.x   :9876

# 可选，仅调度相关服务需要
XXL-Job    2.4.0
Node.js    18+     （仅 front/ 演示端）
需要准备的两个库
-- 用户域：分 100 表，共 300 张分表 + 1 张索引表
CREATE DATABASE xy_live_user DEFAULT CHARSET utf8mb4;
-- t_user_00 ~ t_user_99
-- t_user_tag_00 ~ t_user_tag_99
-- t_user_phone_00 ~ t_user_phone_99
-- t_user_index

-- 公共库：分布式 ID 号段表等
CREATE DATABASE xy_live_common DEFAULT CHARSET utf8mb4;

# 分表规则见：xy-live-user-provider/src/main/resources/xy-db-sharding.yaml
# 建表 SQL 暂未随仓库提供，需按 dao/po 实体自行创建
配置下发规则
# 每个服务在 Nacos 中对应一份配置：
#   Data ID:  ${spring.application.name}.yml
#   Group:    DEFAULT_GROUP

xy-live-gateway.yml            # 端口 9191、路由规则
xy-live-api.yml                # REST 上下文、Dubbo 端口
xy-live-user-provider.yml
xy-live-living-provider.yml
xy-live-gift-provider.yml
xy-live-bank-provider.yml
xy-live-bank-api.yml
xy-live-msg-provider.yml
xy-live-account-provider.yml
xy-live-im-core-server.yml
xy-live-im-router-provider.yml
xy-live-im-provider.yml
xy-live-id-generate-provider.yml

# 本地凭据通过环境变量注入，不要写进 Nacos 公共配置
cp .env.example .env
按依赖方向启动
# 1. 构建（interface / framework 需先 install）
mvn -T 1C clean install -DskipTests

# 2. 基础服务
java -jar xy-live-id-generate-provider/target/*.jar
java -jar xy-live-account-provider/target/*.jar
java -jar xy-live-user-provider/target/*.jar

# 3. 业务服务
java -jar xy-live-living-provider/target/*.jar
java -jar xy-live-gift-provider/target/*.jar
java -jar xy-live-bank-provider/target/*.jar
java -jar xy-live-msg-provider/target/*.jar

# 4. IM 体系
java -jar xy-live-im-core-server/target/*.jar
java -jar xy-live-im-router-provider/target/*.jar
java -jar XY-live-im-provider/target/*.jar

# 5. 接入层
java -jar xy-live-api/target/*.jar
java -jar xy-live-bank-api/target/*.jar
java -jar xy-live-gateway/target/*.jar

# 网关默认监听 9191，路由前缀由 Nacos 配置决定

关于建表脚本

仓库暂未附带完整的 DDL。你需要依据 xy-db-sharding.yaml 中的分表节点与各模块 dao/po 实体自行建表， 这也是当前最影响上手体验的一环，欢迎通过 PR 补充。

Modules

28 个模块，职责单一

按「接口 / 实现」成对拆分，接口模块可被任何服务依赖，实现模块只负责自身业务。

接入层

xy-live-gateway

Spring Cloud Gateway 统一入口，默认端口 9191，路由规则由 Nacos 下发。

xy-live-api

HTTP 聚合层，对外提供直播、礼物、商城、用户与 IM 配置接口，内部通过 Dubbo 编排。

xy-live-bank-api

支付回调入口，接收支付平台异步通知并驱动订单结算。

业务服务

xy-live-user-provider

用户信息、手机号注册登录、用户标签。三级缓存 + 分布式锁 + 按 user_id 分 100 表。

xy-live-living-provider

直播间生命周期、房间列表分页、PK 连麦状态。

xy-live-gift-provider

礼物配置与送礼、红包雨发放领取、SKU / 购物车 / 订单 / 库存。

xy-live-bank-provider

虚拟币账户、交易流水、订单支付与状态订正。

xy-live-account-provider

账户 Token 的签发与校验。

xy-live-msg-provider

短信验证码、IM 业务消息消费与转发。

即时通讯

xy-live-im-core-server

Netty 长连接服务器，处理连接、鉴权、心跳、编解码与消息分发。

xy-live-im-router-provider

IM 消息路由，按用户定位到具体长连接节点。

XY-live-im-provider

IM Token 签发与在线状态查询。

基础支撑与框架

xy-live-id-generate-provider

号段模式分布式 ID 发号器，Dubbo 端口 9103。

xy-live-common-interface

跨服务共享 DTO、枚举、MQ Topic 常量与工具类。

xy-live-framework-*

web / datasource / redis / mq / dubbo / xxljob 六个自研 starter， 收敛异常处理、限流、缓存 Key、MQ 与任务调度装配。
