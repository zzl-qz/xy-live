## 一、模块功能概述

该模块是一个基于Netty实现的即时通讯(IM)核心服务器，主要负责处理客户端的WebSocket和TCP连接，实现用户登录、登出、心跳检测、消息收发等核心IM功能，并通过Redis进行缓存管理、RocketMQ进行消息分发，支持分布式部署环境下的IM服务。

核心功能包括：
- 支持WebSocket和TCP两种协议的客户端连接
- 用户身份验证与登录状态管理
- 心跳机制维持长连接
- 消息的编码、解码与路由转发
- 在线状态管理与用户连接缓存
- 消息确认(ACK)机制确保消息可靠送达
- 集成Redis用于缓存用户连接信息和心跳记录
- 集成RocketMQ实现消息的异步处理与分发

## 二、实现流程

### 1. 连接建立流程
1. **WebSocket连接**：
    - 客户端通过`ws://ip:port/token/userId/code/param`格式的URL发起连接
    - `WsSharkHandler`处理握手请求，验证token合法性
    - 验证通过后调用`LoginMsgHandler`的`loginSuccessHandler`完成登录初始化
    - 保存用户与Channel的映射关系，设置上下文属性

2. **TCP连接**：
    - 客户端通过TCP协议连接服务器
    - `TcpImServerCoreHandler`接收连接请求
    - 客户端发送登录消息，由`LoginMsgHandler`处理身份验证

### 2. 消息处理流程
1. **消息接收**：
    - WebSocket消息由`WsImServerCoreHandler`接收并转换为`ImMsg`对象
    - TCP消息通过`ImMsgDecoder`解码为`ImMsg`对象
    - 由`ImHandlerFactoryImpl`根据消息类型(code)路由到对应的处理器

2. **消息路由**：
    - 登录消息 → `LoginMsgHandler`
    - 登出消息 → `LogoutMsgHandler`
    - 业务消息 → `BizImMsgHandler`
    - 心跳消息 → `HeartBeatImMsgHandler`
    - ACK消息 → `AckImMsgHandler`

3. **消息发送**：
    - 通过`RouterHandlerServiceImpl`查找用户对应的Channel
    - 封装消息为`ImMsg`对象，通过`ImMsgEncoder`编码后发送

### 3. 断开连接流程
1. 客户端主动断开或网络异常导致连接中断
2. 触发`channelInactive`回调方法
3. `LogoutMsgHandler`处理登出逻辑：
    - 移除用户与Channel的映射关系
    - 删除Redis中的缓存信息
    - 发送离线消息到RocketMQ
    - 清理上下文属性

## 三、优秀设计点

1. **协议设计**：
    - 自定义`ImMsg`消息结构，包含魔数(magic)、长度(len)、类型(code)和消息体(body)，便于消息校验和解析
    - 实现`ImMsgEncoder`和`ImMsgDecoder`完成消息的编解码，适配Netty的Pipeline机制

2. **设计模式应用**：
    - 策略模式：通过`SimpleHandler`接口和不同的实现类处理不同类型的消息
    - 工厂模式：`ImHandlerFactory`根据消息类型分发到对应的处理器
    - 单例模式：`ChannelHandlerContextCache`管理全局的Channel缓存

3. **高可用设计**：
    - 心跳机制：`HeartBeatImMsgHandler`定期更新用户在线状态，清理过期连接
    - 消息确认机制：通过ACK消息和延迟检查确保消息可靠送达
    - 分布式支持：使用Redis存储分布式缓存，RocketMQ实现跨服务消息通信

4. **扩展性设计**：
    - 基于接口编程，各组件职责单一，便于扩展新的消息类型
    - 配置化的消息路由，新增消息处理器只需在工厂类中注册
    - 支持WebSocket和TCP两种协议，易于扩展其他协议

5. **资源管理**：
    - 连接关闭时清理相关资源，避免内存泄漏
    - Redis缓存设置过期时间，自动清理无效数据
    - 异常处理完善，确保服务稳定性

## 四、需要补充的点

1. **安全性增强**：
    - 目前的token验证逻辑较为简单，可增加签名机制和过期时间校验
    - 消息传输未加密，敏感信息可能存在泄露风险，建议添加加密传输功能

2. **性能优化**：
    - `ChannelHandlerContextCache`使用HashMap存储连接，在高并发场景下可能存在线程安全问题，建议使用ConcurrentHashMap
    - 消息发送未做流量控制，可添加限流机制防止消息风暴
    - RocketMQ消息发送失败时仅打印日志，建议增加重试机制

3. **功能完善**：
    - 缺少消息存储功能，无法实现消息历史记录查询
    - 未实现群聊功能，仅支持点对点消息
    - 缺少用户状态同步机制，分布式部署时可能存在状态不一致问题

4. **监控与告警**：
    - 缺乏完善的监控指标，如连接数、消息量、处理耗时等
    - 异常情况未接入告警系统，不利于问题及时发现

5. **代码优化**：
    - `WebsocketEncoder`类未完成实现，需要补充完整
    - 部分异常处理直接关闭连接，可增加更友好的错误提示和恢复机制
    - 常量定义分散，建议集中管理所有常量

6. **文档补充**：
    - 缺少API文档，建议使用Swagger等工具生成接口文档
    - 消息协议格式未单独文档化，不利于客户端对接
    - 缺少部署文档和配置说明
